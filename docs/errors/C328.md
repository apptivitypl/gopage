# C328 — loader in a layout

## Message

```
error[GOPAGE-C328]: a layout carries Load, which never runs
help: a layout renders the props of the page below it; move the function to the page
```

## Why this is rejected

A layout has no props of its own. It renders against the props of the page inside it, which is why
`{{ Title }}` in a layout reads the page's `Title`.

A `Load` written in a layout compiles, is never called, and then the layout asks for a field the page
does not have — a 500 at request time from a build that reported nothing. The same holds for `Meta`,
`Submit` and `Sitemap`.

## How to fix it

Move the function to the pages that need it, and let the layout read what they return:

```gopage
---
type Props struct {
	Title string
	Nav   []Link
}

func Load(ctx *gopage.Ctx) (Props, error) { … }
---
```

Values every page shares — navigation, a language switcher, a breadcrumb — are built once in your own
package and returned by each page's loader, so the layout can name them.

## What this check does not cover

Other declarations in a layout's frontmatter. Types and helper functions are fine; only the four
route hooks are refused.
