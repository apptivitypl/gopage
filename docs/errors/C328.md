# C328 — route hook in a layout

## Message

```
error[GOPAGE-C328]: a layout carries Meta, which never runs
help: only a route answers with meta, a form or a sitemap; move the function to the page, and use Load if the layout needs data of its own
```

## Why this is rejected

`Meta`, `Submit` and `Sitemap` belong to a route. One layout wraps many pages, so there is no single
title it could name, no single form it could accept and no single set of addresses it could list.
gopage never calls these in a layout, and a function that compiles, sits in the file and never runs
is worse than one that is refused.

`Load` is different, and is allowed: a layout that needs data of its own declares `Props` and `Load`
like a page, and reads the result under `layout.`.

## How to fix it

Move the route hook to the page:

```gopage
---
type Props struct {
	Title string
}

func Load(ctx *gopage.Ctx) (Props, error) { … }

func Meta(ctx *gopage.Ctx, props Props) gopage.Meta {
	return gopage.Meta{Title: props.Title}
}
---
```

If the layout needed data rather than a route hook, give it its own loader:

```gopage
---
type Props struct {
	Sections []Section
}

func Load(ctx *gopage.Ctx) (Props, error) {
	return Props{Sections: nav.Sections(ctx.Locale())}, nil
}
---
<nav>
  {% for section in layout.Sections %}<a href="{{ section.Href }}">{{ section.Title }}</a>{% endfor %}
</nav>
{% outlet %}
```

The layout's own fields live under `layout.`, and bare names in a layout keep meaning what they
always did: the props of the page inside it. The loader runs once per request, and not at all when
the browser already holds that layout and asks for a partial navigation.

## What this check does not cover

Whether the layout's loader is cheap. Its freshness folds into the page's: the shorter TTL wins, the
tags add up, and a layout that marks itself private keeps the whole page out of the cache.
