# C114 — vary outside a page or a layout

## Message

```
error[GOPAGE-C114]: {% vary %} outside a page or a layout
help: the cache key belongs to the route; move the directive to the page that answers, or to the layout above it
```

## Why this is rejected

`{% vary %}` widens the cache key of a route, so the compiler collects it from the page that answers
and from the layouts above it. A component has no route and no cache entry of its own: it renders
inside whatever page includes it. A directive there would change nothing while looking like it
changes something, and the same component included from two pages would read as though it made both
of them vary.

## How to fix it

Move the directive to the page, or to the layout, that the component renders inside:

```gopage
{% vary cookie="theme" values="light, dark" %}
<article>
  <ThemeToggle />
</article>
```

If several pages share the component and all of them need the dimension, put it in the layout above
them and every page below inherits it:

```gopage
{% vary cookie="theme" values="light, dark" %}
<!doctype html>
<html><head>{% meta %}{% assets %}</head><body>{% outlet %}</body></html>
```

## What this check does not cover

Whether the dimension is a good idea. A cookie named in `security.privateCookies` is refused by
[C330](C330.md), and a route whose dimensions multiply into more entries than `cache.variants`
allows is reported by [W706](W706.md).
