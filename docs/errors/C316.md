# C316 — malformed image

## Message

```
error[RILL-C316]: an image needs a literal width and height
help: write <Image src="/hero.avif" width="1200" height="800" alt="..." /> so the box is reserved before the file arrives
```

## Why this is rejected

An `<img>` without intrinsic dimensions has no box until the file arrives, so everything below it
moves when it does. That shift is measured, it is the one layout metric a framework can prevent
outright, and it cannot be fixed later by the person writing the page — so `<Image>` refuses to
compile without the numbers.

The same code reports a missing `alt`. An image with no alternative text is unusable to anyone who
cannot see it, and the compiler is the last place that can insist.

## How to fix it

```rill
<Image src="/hero.avif" width="1200" height="800" alt="the terrace at dusk" class="hero" />
```

- `width` and `height` are the file's own pixel dimensions, written as literals; CSS may still size
  the element however it likes.
- `alt=""` is the correct answer for decoration — it says "skip this", which is different from
  saying nothing.
- add `eager` to the image above the fold; every other image is `loading="lazy"` already.
- any other attribute passes through to the `<img>`.
