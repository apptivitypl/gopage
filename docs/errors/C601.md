# C601 — missing translation

## Message

```
error[GOPAGE-C601]: listing.title has no translation in pl
help: add listing.title to locales/pl.json, or run gopage i18n sync
```

## Why this is rejected

Every `t("key")` in a template is resolved at build time into a per-locale table, so the manifest
holds finished text and the interpreter never looks a key up by name. A key with no text in one of
the configured locales would ship that locale with the raw key showing on the page.

The check runs only when the project has catalogs at all — a project with no `locales/` directory
is not localised and `t()` falls back to the key.

## How to fix it

Add the key to the catalog:

```json
// locales/pl.json
{
  "listing": {
    "title": "oferta"
  }
}
```

Or let the tool copy the missing keys over from the default locale and mark them for translation:

```bash
gopage i18n sync
```

A key present in the default locale but missing elsewhere resolves through the default locale
during development; it is the production build that refuses.
