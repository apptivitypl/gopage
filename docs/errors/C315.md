# C315 — malformed island

## Message

```
error[RILL-C315]: Badge has no client.ts
help: write components/Badge/client.ts exporting mount(el, props), or drop client=
```

## Why this is rejected

`client=` turns a component into an island: the server renders its markup as usual, writes its
props next to it as JSON, and the browser loads a module that takes over. Without a `client.ts`
there is no module to load, so the attribute would do nothing but add a wrapper element.

The same code reports an activation strategy that does not exist, and `client="media"` without the
query it is supposed to wait for.

## How to fix it

```
components/Search/
  props.go       the typed props, shared by the server and the client
  template.rill  the markup rendered on the server
  client.ts      export function mount(el, props): () => void
```

```rill
<Search client="visible" Placeholder="find" />
```

| Strategy | When the module loads |
|---|---|
| `load` | as soon as the runtime starts |
| `idle` | in the first idle callback |
| `visible` | when the island scrolls into view |
| `media` | when `media="(min-width: 40rem)"` starts matching |

`mount` returns a cleanup function; the runtime calls it when the island leaves the page. Every
island renders on the server first, so the page reads and works before any of this happens.
