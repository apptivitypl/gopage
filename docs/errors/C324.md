# C324 — value interpolated into srcdoc

## Message

```
error[GOPAGE-C324]: a value is interpolated into srcdoc
help: the browser decodes the attribute and parses it as a document, so escaped markup becomes
      markup again; serve the frame a url with src
```

## Why this is rejected

`srcdoc` is the one attribute whose value is not text but a whole HTML document. The browser decodes
the attribute the usual way and then hands the result to the parser, so escaping is undone and the
markup underneath is parsed — inside a frame, as a document.

```gopage
<iframe srcdoc="{{ Props.Bio }}"></iframe>
```

A bio of `<img src=x onerror=alert(document.cookie)>` is escaped correctly on the way out:

```html
<iframe srcdoc="&lt;img src=x onerror=alert(document.cookie)&gt;"></iframe>
```

The tokenizer decodes the attribute to `<img src=x onerror=alert(...)>`, the frame parses that as its
document, the image fails to load, and the handler runs. One decode step turns escaped text back into
executable markup.

This is the same shape as [C323](C323.md): the value crosses a boundary where a second parser gets a
turn, and HTML escaping is spent on the first one.

## How to fix it

Give the frame a URL and let the content travel as a response rather than as an attribute:

```gopage
<iframe src="/embeds/{{ Props.ID }}" title="{{ Props.Title }}"></iframe>
```

The route behind that URL renders through the normal pipeline, so every value in it is escaped for
the context it lands in, and the frame gets the isolation it exists for. Add `sandbox` when the
content is not fully yours.

If the document really is fixed, write it as a literal `srcdoc` with no interpolation — that compiles
unchanged.
