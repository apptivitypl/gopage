# W703 — class built at request time

## Message

```
warning[RILL-W703]: this class list is built at request time
 --> components/Badge/template.rill:1:7
  |
1 | <span class="badge badge-{{ Tone }}">{{ Label }}</span>
  |       ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
  |
  = help: the css engine cannot see it; write :class="{ 'name': condition }" or add the name to safelist
```

## Why this is only a warning

The compiler exports every class literal it can see to `.rill/tailwind-inventory.txt`, and the CSS
engine treats that file as the complete list of classes in use. A class assembled from a value only
known at request time is not in it, so the rule that would style it is removed as unused: the page
renders, the class is on the element, and nothing happens.

It is a warning rather than an error because a `safelist` is a legitimate answer, and because the
class may belong to a stylesheet rill does not generate.

## How to fix it

Write the possibilities out so the compiler can see them:

```rill
<span :class="{ 'badge': true, 'badge-ok': Tone == 'ok', 'badge-muted': Tone == '' }">{{ Label }}</span>
```

The class map compiles to a conditional in the render plan — one jump per entry, no string building
— and every name lands in the inventory.

If the class genuinely cannot be enumerated, add it to the CSS engine's `safelist` and leave the
warning as the record of that decision.
