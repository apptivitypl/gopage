# W704 — seo rule points at no route

## Message

```
warning[GOPAGE-W704]: seo.robots disallow names /nowhere, which no route answers
help: write the path a route actually serves, or drop the rule
```

## Why this is a warning

`robots.txt` rules and sitemap exclusions are strings in `gopage.jsonc`, and a crawler will not tell
you that one of them matches nothing. A typo in `disallow` silently opens a section you meant to
close; a typo in `seo.sitemap.exclude` silently leaves a page in the sitemap.

It is a warning rather than an error because a rule may legitimately name something the route table
does not hold — a path served by a proxy in front of the app, or one that only exists after a
rewrite.

## How to fix it

Name a path some route answers, or drop the rule. Locale prefixes are understood, so `/pl/about`
counts when `/about` is a route and `pl` is a configured locale.

```jsonc
"seo": {
  "robots": { "groups": [{ "userAgent": ["*"], "disallow": ["/api"] }] },
  "sitemap": { "exclude": ["/map"] }
}
```

## What this check does not cover

Rules that carry a wildcard — anything containing `*`, `$` or `?` is left alone, because those match
by pattern rather than by prefix. Reserved prefixes and asset paths always count as served.
