# C319 — malformed fragment placeholder

## Message

```
error[RILL-C319]: only a deferred fragment has a placeholder
help: add defer to the fragment, or drop the placeholder section
```

## Why this is rejected

A placeholder is what stands in the document while the fragment is not there yet:

```rill
{% fragment "Reviews" defer %}
    <ul>{% for review in Reviews %}<li>{{ review.Author }}</li>{% endfor %}</ul>
{% placeholder %}
    <ul><li class="skeleton"></li><li class="skeleton"></li></ul>
{% endfragment %}
```

A fragment without `defer` renders its body where it stands, in the same pass, from props that are
already loaded. There is no moment at which the placeholder would be visible, so the markup would be
compiled into the plan and never reached. Rather than carry dead ops, the compiler asks which of the
two you meant.

The placeholder is not a loading spinner bolted on by the client. It is part of the document the
server sends, which is what makes it work with javascript switched off and what lets that document
be cached: every visitor gets the same shell, and only the fragment is fetched per request.

## How to fix it

Add `defer` if the fragment has a loader:

```rill
{% fragment "Reviews" defer %}…{% placeholder %}…{% endfragment %}
```

A deferred fragment needs a loader function named after it, or the compiler reports
[C318](C318.md) instead:

```go
func Reviews(ctx *rill.Ctx) ([]Review, error) {
	return reviews.Latest(ctx.Context(), 3)
}
```

Or drop the placeholder and keep the fragment as a plain cache boundary:

```rill
{% fragment "Reviews" cache="5m" %}…{% endfragment %}
```
