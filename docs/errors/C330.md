# C330 — vary on a private cookie

## Message

```
error[GOPAGE-C330]: cookie session is named in security.privateCookies, so the response is never cached
help: drop the directive, or take the cookie out of security.privateCookies
```

## Why this is rejected

The two settings say opposite things about the same cookie.

`security.privateCookies` means a request carrying that cookie never becomes a cache entry: the
server checks it before a loader runs, and the answer goes out as `private, no-cache`. `{% vary %}`
means the opposite: the response is shared, and the cookie's value chooses which shared entry it is.

Whichever one you meant, the other is dead. Leaving both in place hides that: the directive reads as
though the page were cached per session, and it never is.

## How to fix it

Decide what the cookie is.

A session belongs in `security.privateCookies`, and the page that reads it is nobody else's:

```jsonc
{"security": {"privateCookies": ["session"]}}
```

A preference — a theme, a market, a unit system — belongs in a `{% vary %}` directive, and the
cookie comes out of `privateCookies`:

```gopage
{% vary cookie="market" values="pl, de, ua" %}
```

The value the loader then reads through `ctx.Cookie` is the bucket, not the raw cookie, so a value
nobody declared cannot leak from one visitor's page into another's.

## What this check does not cover

A cookie that is not in `security.privateCookies` but still identifies one visitor. gopage cannot
tell a theme from a session by its name. If a cookie says who someone is, name it in
`security.privateCookies` and let the page be private.
