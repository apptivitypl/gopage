# C603 — catalog in the old toml format

## Message

```
error[GOPAGE-C603]: catalogs are json files now
help: rewrite locales/pl.toml as json, keeping the same keys and nesting
```

## Why this is rejected

Message catalogs are read by the compiler and, in a project that ships to Workers, their text ends
up in the manifest. JSON is in the standard library, every editor validates it without a plugin,
and every translation tool speaks it — TOML bought nothing here and cost a dependency on the
runtime path.

A project that still has `locales/*.toml` would silently lose those translations, because the
loader no longer reads that extension. Rather than compile a half-translated site, the build stops
and names the file.

## How to fix it

Rewrite the file as JSON under the same name and delete the TOML one. Keys and nesting carry over
unchanged, and plural forms keep their shape:

```json
{
  "reviews": {
    "one": "{count} review",
    "other": "{count} reviews"
  }
}
```

Nothing else changes: `t("listing.title")` in templates stays exactly as it was.

There is no `gopage i18n migrate`. It existed only to read the format gopage has stopped writing, and
keeping it meant carrying a TOML parser in the toolchain for a file that no released version of
gopage ever produced.
