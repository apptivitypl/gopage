# W706 — route asks for too many cache variants

## Message

```
warning[GOPAGE-W706]: route /jobs/[city] asks the cache for 36 variants, and cache.variants allows 16
help: drop a vary directive, shorten one of its value lists, or raise cache.variants
```

## Why this is a warning

Dimensions multiply. A route with a three-value theme and a five-value market does not hold two
entries, it holds `4 × 6 = 24`: every list gains one bucket for the values nobody declared.

The cache is bounded by bytes and evicts by least recent use, so a route that holds two dozen copies
of itself is not an error — it works — but it spends the budget that other routes were going to use,
and each variant is warmed separately, so each one is a fresh render for the first visitor who asks
for it.

It is a warning rather than an error because the number that is too high on a small site is
reasonable on a large one, and only you know which this is.

## How to fix it

Count what the page actually needs. A dimension is worth an entry only when the rendered document
really differs:

```gopage
{% vary cookie="theme" values="light, dark" %}
```

If the difference is one class on `<body>`, it is cheaper as a `data-` attribute and a CSS rule, and
the page stays one entry. If it is a personal element — a name, a basket, a heart — it belongs in an
island over a shared page rather than in the cache key.

When the count is genuinely right, raise the ceiling:

```jsonc
{"cache": {"variants": 48}}
```

## What this check does not cover

The cache budget itself. `cache.variants` counts entries per route; the store is bounded in bytes by
`CacheBytes`, and a route that fits the ceiling can still evict others by being large.
