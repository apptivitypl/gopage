# C323 — value interpolated into an event handler

## Message

```
error[GOPAGE-C323]: a value is interpolated into onclick, an event handler
help: the browser decodes html entities before javascript reads the attribute, so escaping cannot
      hold here; move the behaviour into an island
```

## Why this is rejected

This one is worse than it looks, because the escaping does not merely fall short — the browser undoes
it.

An `on*` attribute holds JavaScript, but it is written in an HTML attribute, so the HTML tokenizer
decodes character references **before** the value is compiled as a program. Whatever the escaper
wrote as `&#39;` is a plain `'` again by the time it matters.

```gopage
<button onclick="pick('{{ Props.Name }}')">go</button>
```

With `Name` set to `');alert(document.cookie);('`, the escaper does its job and the document contains:

```html
<button onclick="pick(&#39;);alert(document.cookie);(&#39;)">go</button>
```

The tokenizer decodes it, and what the browser compiles is:

```js
pick('');alert(document.cookie);('')
```

The escaping was applied, was correct for HTML, and bought nothing. There is no HTML-level escaping
that survives this round trip; a value here must be escaped as JavaScript (`'`), which means
knowing at compile time that this attribute is a program. gopage knows — that is this check — and
refuses rather than pretending.

The check fires on any attribute whose name begins with `on`, matched case-insensitively, that
carries an interpolation or a bound expression. A handler with a fixed body is untouched.

## How to fix it

Behaviour that needs server data belongs in an island, where props arrive as JSON and the browser
attaches the listener:

```gopage
<Picker client="load" :Name="Props.Name" />
```

If the markup should stay server-rendered, keep the handler static and put the value in a data
attribute:

```gopage
<button class="pick" data-name="{{ Props.Name }}">go</button>
```

```ts
document.querySelectorAll(".pick").forEach((button) => {
  button.addEventListener("click", () => pick(button.dataset.name));
});
```

The data attribute is a normal HTML context, and the listener reads it as a string that no one parses
as source.
