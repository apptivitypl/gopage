# C318 — malformed deferred fragment

## Message

```
error[GOPAGE-C318]: Reviews is deferred but the go block has no func Reviews
help: write func Reviews(ctx *gopage.Ctx) (T, error) in the --- block, or drop defer
```

## Why this is rejected

`{% fragment "Reviews" defer %}` splits the document at that point: the server sends everything
above it, runs the loader, and sends the fragment when the data arrives. Two things have to hold for
that to work.

**The fragment needs a loader.** The loader is a function whose name is the fragment's name, taking
the context and returning a value and an error. Inside the fragment that value reads exactly like a
field of the props — the only difference is when it exists. Without the function there is nothing to
wait for.

**The fragment has to be a boundary in the document.** A deferred fragment inside a loop, inside a
branch or inside a component is not one region of the page but zero, one or many, and there is no
single point at which the server could split the response. The compiler rejects those positions
instead of guessing.

## How to fix it

Write the loader next to `Load`:

```gopage
---
type Review struct {
	Author string
	Body   string
}

type Props struct {
	Heading string
}

func Load(ctx *gopage.Ctx) (Props, error) {
	return Props{Heading: "reviews"}, nil
}

func Reviews(ctx *gopage.Ctx) ([]Review, error) {
	return reviews.Latest(ctx.Context(), 3)
}
---
<h1>{{ Heading }}</h1>

{% fragment "Reviews" defer %}
	{% for review in Reviews %}
		<blockquote>{{ review.Body }} — {{ review.Author }}</blockquote>
	{% endfor %}
{% endfragment %}
```

If the fragment has to live inside a loop, load its data in `Load` and drop `defer`: a fragment
without `defer` still caches on its own, it just does not split the response.

Several deferred fragments on one page load in parallel, so the page waits for the slowest one, not
for their sum.

## Loading the fragment on demand

`defer` on its own means the fragment is fetched as soon as the document is parsed. A strategy
delays that until the slot is worth fetching:

```gopage
{% fragment "HackerNews" defer="visible" %}
```

- `defer="visible"` — the client fetches when the slot scrolls into view, or when whatever hid it
  (a closed tab, a collapsed section) makes it visible;
- `defer="idle"` — the client fetches once the main thread is idle;
- plain `defer` — fetched immediately, the behaviour before strategies existed.

A strategy only means something with `[fragments] deferred = "fetch"`, where the fragment is a
second request the client makes on its own. With `inline` and `tail` the content travels inside the
same response, so there is no later moment to wait for, and the compiler refuses the combination:

```
error[GOPAGE-C318]: defer="visible" needs [fragments] deferred = "fetch"
help: the other modes send the fragment inside the same response, so there is nothing left to wait for
```

In the document the strategy rides on the `fetch` attribute itself — a bare `fetch` means
"straight away", a value means "when this happens":

```html
<gopage-slot name="HackerNews" fetch="visible">
```

Where the browser has no `IntersectionObserver`, `visible` fetches straight away rather than never.
