# C317 — malformed client script

## Message

```
error[GOPAGE-C317]: <script client> belongs to a component
help: move the island into components/, or use a plain <script> tag for page javascript
```

## Why this is rejected

`<script client>` turns a component into an island: the block is cut out of the render plan, handed
to the bundler as its own module, and loaded in the browser according to the `client=` strategy of
the tag that uses it. That only means something for a component — a page has no props to hand over
and no activation boundary to hang the code on.

Four shapes are rejected:

- a `<script client>` in `app/page.gopage` or `app/layout.gopage`, where there is no component to attach
  it to;
- a second `<script client>` in one component, because an island has exactly one entry module;
- a block that exports neither `mount` nor a default component, which would load in the browser and
  do nothing;
- a block that exports both, because the bundler could not tell which one is the island.

```
error[GOPAGE-C317]: <script client> exports neither mount nor a default component
help: export function mount(el, props) and return a function that undoes what it set up, or export
      default a react component
```

An ordinary `<script>` tag without the `client` attribute is left alone — it is markup like any
other and ships as written.

## How to fix it

Put the block in a component and export `mount`:

```gopage
---
type Props struct {
	Start int
}
---
<output>{{ Start }}</output>
<button type="button">+1</button>

<script client>
import type { Props } from "gopage:props/Ticker";

export function mount(element: HTMLElement, props: Props): () => void {
	const output = element.querySelector("output")!;
	let value = props.Start;
	const step = () => { output.textContent = String(++value); };
	element.querySelector("button")!.addEventListener("click", step);
	return () => element.querySelector("button")!.removeEventListener("click", step);
}
</script>
```

`mount` receives the element and the props, and returns the function that undoes what it set up —
the runtime calls it when the island leaves the page during navigation.

A component too big for one file keeps the old shape: `components/Ticker/template.gopage`,
`props.go` and `client.ts` side by side. Both layouts compile to the same island.

## A React component instead of `mount`

A block with `lang="tsx"` (or a `client.tsx` file) that `export default`s a React component is an
island too. The compiler wraps it into the same contract — `createRoot` on the island's element,
`render` with the props, and `unmount` as the cleanup:

```gopage
---
type Props struct {
	Points string
}
---
<div class="chart"><span class="skeleton"></span></div>

<script client lang="tsx">
import { useState } from "react";
import type { Props } from "gopage:props/Chart";

export default function Chart(props: Props) {
	const [picked, pick] = useState<number | null>(null);
	return <div className="chart">{props.Points.split(",").map((point, index) => (
		<button key={index} type="button" onClick={() => pick(index)}>{point}</button>
	))}</div>;
}
</script>
```

The markup above the script is what the server sends and what the visitor sees first; React replaces
it when the island activates. React itself comes from the project's `node_modules` and lands in one
shared chunk, fetched the first time a React island activates.
