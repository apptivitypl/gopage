# C320 — private value on an island

## Message

```
error[RILL-C320]: Session.Email reaches the browser: Search is an island
help: everything passed to <Search> is written into the document as json; pass what the browser
      needs, not the private value
```

## Why this is rejected

An island is the one component whose props leave the server. The compiler writes them into the
document as a JSON block that the browser reads on hydration:

```html
<rill-island name="Search" strategy="load"><script type="application/json">{"Placeholder":"find"}</script>
```

That block is part of the response. Anyone who can open the page can read it, and so can anything
that caches the page. A field marked `rill:"private"` is one you have told the compiler belongs to a
single visitor, so serialising it is the one thing that must never happen to it.

The check covers three shapes:

- a private field passed straight in — `<Search :Token="Session.Token" />`;
- a field reached through a private struct, because privacy travels down the whole path;
- a private value parked in a local first — `{% let held = Session.Token %}` then `:Token="held"`.

A plain component is not affected. Its props are read by the interpreter and never written out, so
`<Badge :Label="Session.Email" />` compiles and renders on the server as it always did.

## How to fix it

Pass what the browser actually needs, not the value it must not see:

```rill
<Search client="load" :Placeholder="Viewer.Name" />
```

If the island needs to act on the private value, keep the value on the server and give the browser a
handle instead — an id, a signed token with a short life, or an endpoint the island calls:

```rill
<Cart client="idle" :Endpoint="'/api/cart'" :Count="len(Cart.Items)" />
```

If the field is not private after all, drop the tag:

```go
type Props struct {
	Viewer  Viewer
	Session Session `rill:"private"`
}
```

## The other shape of this error

An island whose own `Props` declares a private field is rejected on the declaration, because the
combination cannot be satisfied — every field of an island's props is serialised:

```
error[RILL-C320]: Props.Token is private and Search is an island
help: island props are serialised into the document for the browser to read; drop the private tag,
      or move the value out of the island
```

## What the check does not do

Privacy is declared, not inferred. A field is private when it carries the tag, and a path is private
when any segment on the way to it is. Reading the body of `Load` to work out that a value came from
a session is not done, exactly as in [C503](C503.md). The tag is the contract.
