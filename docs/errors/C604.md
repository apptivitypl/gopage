# C604 — message argument mismatch

## Message

```
error[GOPAGE-C604]: jobs.in_city in pl wants {city}, and the call does not pass it
help: write t("jobs.in_city", city = …)
```

## Why this is rejected

A message with a placeholder needs a value for it. Without the check, `{city}` reaches the page
verbatim — a heading that reads "Praca w {city}" in production, in one locale only, because the other
catalogs happened to be written without the placeholder.

The check runs per locale, so a placeholder added to the Polish text but not to the English one is
reported against the call that would render it.

## How to fix it

Pass every placeholder the message uses, by name:

```gopage
<h1>{{ t("jobs.in_city", city = City) }}</h1>
```

```json
{"jobs": {"in_city": "Praca w {city}"}}
```

`count` keeps its own role: it selects the plural form and fills `{count}`.

```gopage
{{ t("jobs.count", count = Total) }}
```

An argument the message does not use is refused the same way — drop it, or add the placeholder.

## What this check does not cover

Whether the value makes sense. The compiler matches names, not meanings.
