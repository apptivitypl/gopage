# C112 — route claims a built-in endpoint

## Message

```
error[GOPAGE-C112]: app/sitemap.xml/route.go answers /sitemap.xml, which gopage serves itself
help: set "seo": {"sitemap": {"mode": "off"}} to answer /sitemap.xml yourself
```

## Why this is rejected

`/sitemap.xml`, `/robots.txt` and the sitemap shards under `/sitemap/` are answered by the
framework. Both they and the routes of a project land on one `http.ServeMux`, and a mux panics on a
duplicate pattern — so without this check the build stays green, the binary compiles, and the server
dies on the first call to `Handler()`. A `public/robots.txt` file reaches the same mux by a different
door and fails the same way.

## How to fix it

Decide who owns the path. To keep the built-in generator, move your route somewhere else:

```
app/sitemaps/hubs.xml/route.go     →  /sitemaps/hubs.xml
```

A second sitemap does not need a route of its own — name it in the configuration and the built-in
`robots.txt` will point crawlers at it:

```jsonc
"seo": { "robots": { "sitemaps": ["/sitemaps/hubs.xml"] } }
```

To take the path over, turn the generator off. The framework then stops serving it, and the link
checker starts holding `href="/sitemap.xml"` to your own route table:

```jsonc
"seo": { "sitemap": { "mode": "off" } }
```

## What this check does not cover

Only the paths the framework serves itself. Two routes of your own that answer the same pattern are
reported as [C101](C101.md).
